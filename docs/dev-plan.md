# 開発計画

仕様書 `docs/spec.md` の「開発計画」（ステップ0〜10）をベースに、レビュー（`docs/spec-review.md`）で見つかった不足を各ステップへ割り当て、作業単位まで分解したもの。

- 規模の目安：S＝1回の依頼で終わる／M＝2〜3回／L＝4回以上
- 各ステップは「完了条件をテストとして先に書く → 実装 → テストが通る → デプロイ → 実機確認」の順
- ⚠ はレビューで追加した項目

## 全体の流れ

```
P 準備 ─▶ 0 試作 ─[判定:描画方式]─▶ 1 土台・読み書き ─▶ 2 表示・再生 ─▶ 3 移調 ─▶ 4 編集・保存 ─▶ 5 PDF
                                                                                            │
                                                                                     [判定:MVP完成]
                                                                                            ▼
                         9 MIDI ◀─ 8 Googleドライブ ◀─[判定:編曲完成]◀─ 7 大編成 ◀─ 6 半自動編曲
                           │
                           ▼
                        10 OMR
```

## ディレクトリ構成（案）

```
src/
  core/                 # 画面に依存しない純粋なTypeScript（Vitestの対象）
    model/              #   型定義（Score, Note, Project…）、schemaVersion変換
    theory/             #   Pitch・Interval・Fraction・調号・異名同音
    musicxml/           #   MusicXML ⇔ 内部データ（読み込み・書き出しはここだけ）
    transpose/          #   モードA・モードB、単旋律抽出
    edit/               #   編集コマンド（undo可能な操作単位）
    check/              #   音域・演奏性チェック
    arrange/            #   解析・割当・縮約・オクターブ調整（ステップ6〜）
    playback/           #   再生用イベント列の生成（繰り返し展開）
  workers/              # Web Worker（Verovio、移調・編曲計算）
  render/               # 描画ライブラリのラッパ（差し替え可能にする）
  audio/                # Tone.js、サンプル読み込み
  storage/              # IndexedDB、ファイル保存、Googleドライブ
  ui/                   # React画面（screens / components / layouts）
config/
  instruments.json      # 楽器定義（音域・移調・音部記号・音色）
  ensembles.json        # 編成（木管5重奏、後で金管5重奏など）
  thresholds.json       # 警告・編曲判定の閾値
test-assets/
  LICENSES.md           # 素材ごとの入手元・ライセンス・作成ソフト
tests/
  e2e/                  # Playwright（画面・性能）
```

## ステップ3：移調（M〜L）

| 作業 | 内容 |
| --- | --- |
| 3-1 | `core/transpose` モードA：調指定／音程指定、上下、♯系♭系、範囲・パート指定、⚠範囲の前後に調号変更を自動挿入、7つ超の異名同音置換（オプション） |
| 3-2 | モードB：楽器の移調情報から記譜音・調号を計算（描画・書き出し時に変換、データは実音のまま）。⚠調号の♯/♭系の選択ルール |
| 3-3 | 「異名同音で簡単にする」ボタン |
| 3-4 | ⚠ 単旋律抽出の最小版：ピアノの右手から最高音を拾い、新しいパート（楽器指定）を作る |
| 3-5 | ⚠ 音域チェック（音域外を赤表示、オクターブ移動の候補）。演奏性チェックはステップ6 |
| 3-6 | 移調パネルUI、Web Workerで計算 |
| 3-7 | テスト：全12調×主要音程の往復一致（自動置換オフ）、B♭クラ譜でAメジャー→Bメジャー・B♭メジャー→Cメジャー、Aクラ・F管ホルン・B♭トランペット・E♭アルトサックスの綴り |

**完了条件**：移調テストがすべて通る。K.331をB♭へ移調→旋律をB♭クラのパートとして抽出→Cメジャーで表示される。曲全体の移調がPC 1秒・スマホ2秒以内。

**結果（2026-10-24）**：完了。
- モードA：調指定／音程指定、上げる・下げる、調号の♯系・♭系（自動は♯♭7つ超だけ異名同音の調へ）、パート・小節範囲の指定。範囲の前後には調号の変更を自動で入れる。一部のパートだけのときは調号を変えず臨時記号で書く（調号は全パート共通のため）
- モードB：元のパートを複製して楽器を指定。和音を弾ける楽器（ピアノ・弦）から単旋律の楽器を作るときは、いちばん高い音を拾って旋律を取り出す（装飾音も残す）。移調楽器の調号は記号の少ない方（同数なら♯系）が既定で、パートごとに♯系・♭系を選べる
- 音域チェック：表示中のパートの音域外の音を赤く表示し、一覧からオクターブ移動の候補どおりに直せる
- 「異名同音で簡単にする」「元の楽譜に戻す」、編集後の楽譜を MusicXML で書き出し
- 完了条件：K.464（K.331 の代わり、イ長調）を B♭ へ移調 → 第1ヴァイオリンから B♭クラのパートを作ると Cメジャーで表示（画面テストで確認）
- 速さ：合成オーケストラ全体の移調 約20ミリ秒（目標1秒）。速いので Worker には分けていない
- 往復一致：全12調×主要13音程×上下で、移調→逆移調が元と一致（異名同音の置換なし）
- 表示の切り替えの名前を「移調／実音」から「記譜／実音」に変えた（移調パネルのボタンと区別するため）

| 作業 | 内容 |
| --- | --- |
| 4-1 | `core/edit`：編集をすべて「コマンド」（実行・取り消し）として実装。undo/redo 100回 |

| 4-6 | 入力：PC（クリック・Shift範囲・キーボード）、タブレット／スマホ（鍵盤パネル・下部ツールバー・始点→終点タップ） |
| 4-7 | ⚠ 単旋律抽出の手直し（音ごとに別声部の音へ差し替え） |
| 4-8 | IndexedDB自動保存（編集後3秒）、⚠`navigator.storage.persist()`、⚠プロジェクトJSONの「ファイルに保存／ファイルから開く」 |
| 4-9 | ⚠ 落ちたあとの復元確認 |

**完了条件**：K.331を10か所編集→書き出し→MuseScoreで一致。リロードしても編集が残る。編集反映がPC 0.2秒・スマホ0.3秒以内（Playwrightで計測）。

**結果（2026-10-25）**：完了。
- 編集はすべて純粋な関数（コマンド）で、結果の楽譜と「変わった小節」を返す。元に戻す／やり直しは100回まで（リロード後は戻せない）
- 選択：音符をタップで1音、五線の空いたところをタップで1小節を範囲で選ぶ。Shift＋クリックか「範囲」ボタンで範囲を広げる
- 下部の編集バー：音高・音価（上書き方式）・付点・3連符・休符・タイ・スラー・アーティキュレーション・強弱。範囲ではコピー・貼り付け・消去・オクターブ・別の楽器へ移す・小節の挿入と削除・拍子・調号
- 入力：鍵盤パネル（C2〜C7）、PC は MuseScore に近いキー操作（A〜G で音名、Shift で和音、↑↓ で半音、Ctrl+↑↓ でオクターブ、1〜7 で音価、. で付点、0／Delete で休符、T タイ、S スラー、J 異名同音、Ctrl+Z／Y）
- 拍が足りなくなった小節は休符で埋め、あふれた小節は赤く表示。音域チェックも編集のたびに出し直す
- 4-7：取り出した旋律の音を選ぶと「元の別の音」から元のパートの同じ位置の音に差し替えられる
- 描き直しは編集した小節を含むチャンクだけ
- 保存：IndexedDB に自動保存（編集が止まって3秒後と、画面を離れるとき）。ホームにプロジェクト一覧（開く・名前の変更・削除）。プロジェクトJSON（.gakufu.json）をファイルに保存／ファイルから開く。`navigator.storage.persist()` を頼み、消されることがある環境ではファイル保存を案内
- 開いたまま終了したプロジェクトは、次に起動したとき「続きを開く」を尋ねる
- 完了条件：
  - K.464（K.331 の代わり）を10か所編集 → 書き出し → MuseScore 3 で読み書き → 読み戻して一致（`npm run check:musescore-edits`）
  - リロードしても編集が残る（画面テスト）
  - 編集反映（ボタンを押してから音が動いた描画まで、第1ヴァイオリン表示、中央値）：PC 48ms・タブレット 65ms・スマホ 60ms（Playwright、この開発環境）
- 残り：実機での操作感の確認（特にスマホの小さい音符のタップ）

## ステップ6：半自動編曲（L、3回に分ける）

| 作業 | 内容 |
| --- | --- |
| 6a | `core/arrange` 解析・割当（純関数）：区間の区切り、役割推定（⚠旋律の高/中の基準）、初期割当、旋律ローテーション |
| 6b | 縮約（⚠和音推定）、オクターブ調整、演奏性チェック（息継ぎ・跳躍・ホルン高音・音域端・旋律欠け）。`config/thresholds.json` |

**完了条件**：アイネ・クライネ第1楽章を木管5重奏にし、警告ゼロまで直せる。

**6a の結果（2026-10-25）**：`src/core/arrange`（analyze.ts・assign.ts）。画面はまだない（6c）。
- 編曲の単位：パート（段が2つ以上なら段ごと、id は `partId#段`）。ティンパニ・打楽器は除く
- 区間：練習番号 → 全休止のあと → 8小節ごと
- 集計：休符の割合、平均音高（いちばん上の音、長さで重み付け）、音の数、拍の頭で最低音を受け持つ割合、鳴り始めの時刻
- 役割：休み（休符80%以上）→ 旋律（音の数が中央値以上で平均音高が最高。G5以上なら高）→ バス → 重複（旋律かバスとリズム90%以上一致かつ同じ音名）→ 対旋律（旋律とのリズム一致60%未満で、音の数が旋律の半分以上）→ 和声
- 割当：役割ごとの候補（`config/ensembles.json` の roles）から空いている楽器へ。候補が埋まっていれば音域の近い空いた楽器へ。余った楽器は音域の近い単位を重ねる
- 旋律の回し：同じ楽器が2区間続けて旋律なら、次の区間は第2候補へ（オプション）
- しきい値は `config/thresholds.json`
- テスト：役割の推定、区間の区切り、割当、旋律の回し、K.464 で第1ヴァイオリンが旋律・チェロがファゴットになる区間が6割超

**6b の結果（2026-10-25）**：`src/core/arrange`（build.ts・check.ts）。画面はまだない（6c）。
- 編成の楽譜を作る：楽器ごとに割り当てた元の単位から1音の線を取り出す。旋律・対旋律は上の音、バスは下の音、和声はほかの楽器が鳴らしていない音名を「3度 → 7度 → 根音 → 5度」の順で
- 和音の推定：鳴り始めの音名の集合を三和音・七の和音の型と照合（5度の省略は可）
- 重ねて受け持つ楽器（余った楽器・候補が重なったとき）は、楽器の音域の真ん中の側へ1オクターブ動かす
- オクターブ調整：区間ごとに線を丸ごと動かし、はみ出す音だけ1音ずつ動かす。線の形を保つ方を優先
- 強弱・ヘアピンなどは写し、arco・pizz. などの弦の指示は写さない。区間をまたいで切れたタイ・スラーは外す
- 生成した音は origin: 'generated'、元の音を derivedFrom に持つ（6c の手直しの区別に使う）

- K.464 → 木管5重奏：約0.1秒、警告18件（音域の端11・息継ぎ6・ホルン高音1）。MusicXML に書き出して読み戻せる
- 管楽器向けの直し（2026-10-25 追加）：トレモロの記号は外す、同じ高さの16分音符以下の刻み（4つ以上）は1つの長い音にまとめる、pizz.（arco まで）の音にはスタッカート。候補を出すのでなく自動で行う（気に入らなければ手で直す）

**6c の結果（2026-10-25）**：編曲の作業画面。

## ステップ9：MIDI読み込み（M） / ステップ10：OMR（L）

仕様書どおり。ステップ10は当面「外部ツール（Audiveris等）でMusicXML化して取り込む」案内で代替し、組み込みはサーバー構成を別途検討。

**ステップ9の結果（2026-10-25）**：`src/core/midi`（parse.ts・toScore.ts・compare.ts）。
- 標準MIDIファイル（形式0・1）を読み、MusicXML を経ずに内部データへ直接変換する（後の表示・移調・編曲・書き出しは同じ）
- パート：トラック × チャンネル。楽器はトラック名、なければ GM の音色番号から。名前が重なれば番号を付ける。打楽器（チャンネル10）は読まない
- 音の長さ：16分音符の格子にそろえる。拍ごとに8分3連符の格子の方が合えば3連符にする
- 小節：拍子の印から。最初の短い小節は弱起として扱う（MuseScore は弱起を 1/4 などで書く）
- 調：調号の印があれば使い、なければ音名ごとの長さから推定（Krumhansl）。綴りは調に合わせる
- 声部：ピアノなど2段の楽器は中央ハで右手・左手に分ける。同時に始まり同時に終わる音は和音、重なる音は2声部まで
- 強弱：小節ごとの音の強さの平均から pp〜ff を推定して、変わったところに書く
- 完了条件：同じ曲の MIDI と MusicXML の一致率を表示できる（`npm run check:midi -- 曲.mid 曲.mxl`。繰り返しは展開して比べる）。K.464（MuseScore で書き出した MIDI）で高さ・長さとも 99.9%。時間を ±1/8 16分音符ずらしても 99.9%
- 残り：人が弾いて録った MIDI（ずれが大きい・テンポが揺れる）での確認、3連符以外の連符、6/8 などの複合拍子の拍の扱い

**ステップ10の結果（2026-10-25、軽い版）**：計画どおり、読み取りの組み込みはせず外部ツールで代替。
- ホームに「楽譜の画像・PDFから作るには」の案内（Audiveris・MuseScore で MusicXML にして開く、スキャンのこつ）
- PDF・画像（PNG・JPEG・GIF・WebP・TIFF・BMP）を選んだら、読み込めない理由と案内を出す
- 読み取りソフトの結果によくある「拍の数が合わない小節」：読み込み確認画面で「拍の足りない小節を休符で埋める」（既定でオン）。多すぎる小節は開いたあと赤く表示する
- 残り：サーバーで読み取りを組み込むかどうか（使ってみて必要になったら判断）
