## 1. 仕様内の矛盾・計画との食い違い

| # | 重要度 | 内容 | 提案 |
| --- | --- | --- | --- |
| 1-1 | A | **単旋律の抽出がどのステップにもない**。機能一覧ではv2だが、ステップ3の完了条件（K.331をB♭クラ譜で表示）とMVP判定（K.331をクラリネット用に移調・手直し・印刷）はピアノ2段譜→クラ1段の変換が前提 | 「最高音を拾う」最小版をステップ3に前倒し。手で別声部へ差し替える機能はステップ4（編集）に含める |
| 1-2 | A | **パートの楽器を変更する操作が定義されていない**。モードBの「楽器を選ぶ」が「既存パートの楽器を差し替える」のか「新しいパートを作る」のか不明 | 「パートを複製して楽器を指定」（元のピアノ譜は残す）を推奨。移調パネルに「この旋律を○○用パートとして作る」を置く |
| 1-3 | A | **「移調を元に戻すと完全一致」と「♯/♭7つ超で異名同音の調へ自動置換」が両立しない**。置換は綴りの情報を捨てる変換なので、往復させると臨時記号の綴り（G♯⇔A♭など）が元に戻らない場合がある。例：Eメジャー→長3度上→G♯メジャー（♯8）→A♭メジャーに置換→長3度下→F♭メジャー（♭8）→Eメジャーに再置換、の途中で臨時記号の綴りが変わりうる | 往復一致テストは「自動置換オフ」で保証する、と明記。置換ありの場合は「実音（MIDI番号）が一致」を条件にする |
| 1-4 | B | 「音域・演奏性チェック」はv2なのに、移調後の音域外赤表示（ステップ3）と「編集するたびに音域・演奏性の警告を再計算」（ステップ4）はMVP | MVP＝**音域チェックのみ**、演奏性（息継ぎ・跳躍・ホルン高音）＝v2、と分ける |
| 1-5 | B | 画面・機能の一部が担当ステップ未定：ホーム画面（プロジェクト一覧）、読み込み確認画面、エラー処理、クラッシュ復元、PWA化、パート譜の生成 | 下記の開発計画（`docs/dev-plan.md`）で割当済み |
| 1-6 | C | 表示オプションの「色分け：編曲元パートごと」「手直しした音の表示」はv2の編曲がないと意味がない | MVPでは項目を出さない（または無効表示） |
| 1-7 | C | 機能一覧で「音符の編集」「表示オプション」（MVP）が表の末尾にあり、v3の後ろに並んでいる | 表の並び替えのみ |

## 2. データモデルの不足（`Score` 型）

最も手戻りが大きい部分。ステップ1でschemaVersion 1を確定する前に埋める。

| # | 重要度 | 不足 | 提案 |
| --- | --- | --- | --- |
| 2-1 | A | **音部記号（clef）がない**。対応要素に入っているのにモデルに置き場がない。小節途中・staffごとに変わる | `ClefChange { partId, staff, measure, onset, sign, line, octaveChange }` を追加 |
| 2-2 | A | **元ファイルの移調楽器（`<transpose>`）の扱いが未定義**。運命はクラ（B♭）、ホルン（E♭）、トランペット（C/E♭）を含む。MusicXMLは記譜音で書かれているので、読み込み時に実音へ変換しないと全編曲が狂う | 読み込み時に `<transpose>` を読んで実音化、`Part.instrumentId` に移調情報を持たせる。書き出し時は**記譜音＋`<transpose>`**で出す（MuseScore等の標準） |
| 2-3 | A | **和音の一部だけのタイが表せない**（`tie` が Note 単位、`pitches` は配列） | `pitches: { pitch: Pitch; tie?: {...}; accidentalShown?: ...; id }[]` のように音単位の属性にする |
| 2-4 | A | 連符の**開始・終了（グループ）**が表せない。`{actual, normal}` だけでは隣り合う3連符の境目や入れ子が不明 | `tuplet: { id, actual, normal, normalType?, start?, stop? }[]`（入れ子対応で配列） |
| 2-5 | A | スラーが `'start'|'stop'` 1つだけ。重なったスラー・番号なし | `slurs: { id, type: 'start'|'stop' }[]` |
| 2-6 | A | **小節番号の意味が未定義**。弱起（0小節）、番号の重複、「12a」のような表示番号、繰り返し括弧内の番号 | 内部は `index`（0始まりの連番）と `displayNumber: string` を分ける |
| 2-7 | A | **プロジェクト全体の型がない**。元スコア・移調後スコア・編曲スコア・編曲の対応表・表示設定がどう関係するか不明 | `Project { schemaVersion, sourceScore, derivedScores[], arrangements[], settings, history? }` を定義。派生スコアは元のコピーとして持つ（非破壊） |
| 2-8 | A | **編曲の対応表のデータ構造がない**。「割当をやり直しても手直しを消さない」を実現するには、生成音がどの区間・どの元パート・どの元音符から来たかが必要 | `Note.derivedFrom?: { sectionId, sourcePartId, sourceNoteIds[] }`、`Arrangement { sections[{ id, startIdx, endIdx, mapping: {target→source[]}, roles }] }`。再割当時は `origin:'edited'` を残し、重なる生成音だけ差し替えるルールを明記 |
| 2-9 | B | 強弱が音符の属性だけ。**ヘアピン（cresc./dim.）・小節途中のテンポ変化・rit.・フェルマータ**がない | `Direction { partId, measure, onset, kind: 'dynamic'|'wedge'|'tempo'|'text'|..., ... }` を別配列で持つ |
| 2-10 | B | テンポに基準音価がない（付点4分=60 等） | `tempo: { bpm, beatUnit: Fraction }` |
| 2-11 | B | D.C.／D.S.／Coda／Fine がない（再生時の展開に必要） | `MeasureMeta.jump?: {...}` を追加。v1はD.C./D.S. al Fine/Codaまで |
| 2-12 | B | 「保持のみ」の要素（歌詞・コード記号・運指・トリル）の置き場がない | `Note.passthrough?: unknown`（元XML断片）として持ち、書き出し時にそのまま戻す |
| 2-13 | B | 表示用の臨時記号情報（注意臨時記号・括弧付き）を保持しない | `accidentalShown?: 'auto'|'courtesy'|'paren'` |
| 2-14 | B | `alter` が ±2 まで。ダブルシャープの音をさらに増1度移調すると±3になり型が破綻 | 移調結果が±3以上なら**自動で異名同音化**（例外ルール）と明記 |
| 2-15 | B | 調号・拍子が全パート共通（`MeasureMeta`）。パートごとに違う拍子（ポリメーター）は非対応でよいか | 非対応と明記。調号は実音で全体共通、記譜時にパートごとに計算 |
| 2-16 | B | 装飾音の `onset`/`duration` の扱い（拍に数えない）、スラッシュ有無 | `grace?: { slash: boolean }`、`duration` は表示上の音価、拍計算からは除外 |
| 2-17 | B | 楽器設定ファイルの形式がない | 下記「楽器定義」参照 |
| 2-18 | C | オッターヴァ（8va）、トレモロ記号、パートグループの括弧、パート略称 | トレモロは縮約の判定に使うので「対応」へ。8vaは表示のみ保持 |
| 2-19 | C | 調の `mode` が major/minor のみ（教会旋法の曲） | 読み込み時に major 扱いに丸め、`modeRaw` を保持 |

### 楽器定義（提案）

```ts
type InstrumentDef = {
  id: string; name: { ja: string; en: string }; abbr: string;
  transposition: { interval: Interval; direction: 'down'|'up' } | null; // 記譜→実音
  range: { practical: [Pitch, Pitch]; extreme?: [Pitch, Pitch] }; // 実音
  clefs: { default: Clef; alt?: { clef: Clef; above?: Pitch; below?: Pitch }[] };
  polyphonic: boolean;     // 和音を置けるか（ピアノ等）
  staves: number;
  midiProgram: number; sampleSet: string;
  keySignaturePolicy?: 'normal'|'none'; // ホルンの慣習
};
type Ensemble = { id: string; name: string; instruments: string[] };
```

「設定ファイルで変更」は、**v1はリポジトリ内JSON（変更＝再デプロイ）**、アプリ内の設定画面で上書きはv2以降、を推奨。

## 3. 移調まわりの不足

| # | 重要度 | 不足 | 提案 |
| --- | --- | --- | --- |
| 3-1 | A | **範囲・パート単位のモードA適用が破壊的か非破壊か**。また部分移調すると区間の前後で調が変わるので、調号変更をどこに入れるか | 適用は「派生スコアを作る（または現スコアを書き換えて undo 可能）」。範囲移調では区間頭と区間直後に調号変更を自動挿入 |

| 3-3 | B | 音程指定で増・減音程、複音程（オクターブ超）を扱うか | 完全・長・短・増・減 × 1〜8度＋オクターブ数、を入力可能にする |

## 4. 音符編集の不足

| # | 重要度 | 不足 | 提案 |

## まず決めてほしいこと（Aのうちユーザー判断が必要なもの）

1. **単旋律抽出（最小版）をMVP（ステップ3）に前倒しする**か → 推奨：前倒し
2. **移調楽器向けパートは「元パートを複製して楽器を指定」方式**でよいか → 推奨：はい
3. **音価変更は「上書き」方式**（後続を削る）でよいか → 推奨：はい
4. **往復一致テストは異名同音の自動置換オフで保証**、でよいか → 推奨：はい
5. **MVPに「ファイルとして保存／開く」（プロジェクトJSON）を入れる**か（Safariのデータ消去対策） → 推奨：入れる
6. 運命のCC0データが見つからない場合の**代替曲** → 推奨：OpenScoreにある2管編成の交響曲（ハイドン・モーツァルト等）

それ以外は上の表の「提案」を既定として進め、仕様書（`docs/spec.md`）へ反映してから実装する。
